## What it is

`SparkSession` is the single entry point to Spark's DataFrame and Dataset API. It wraps a `SparkContext` (which owns the cluster connection and scheduler) inside a richer SQL-aware layer that also holds a `SharedState` (warehouse, cache, external catalog — shared across sessions on the same JVM) and a `SessionState` (SQL config, temp views, UDFs, parser — isolated per session). The fluent `Builder` API collects configuration before constructing or reusing a session; two class-level slots — a thread-local active session and a global default session — govern reuse and isolation throughout the application lifetime.

### What the session actually owns — `SharedState` vs `SessionState`

This is the distinction that makes `newSession()` and `cloneSession()` comprehensible, and the earlier trace named the two objects without tracing either.

- [SharedState.scala:51](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/internal/SharedState.scala#L51) — **one per `SparkContext`**, shared by every session on the JVM. Owns:
  - [`cacheManager`](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/internal/SharedState.scala#L98) (L98) — which is why `df.cache()` in one session is visible to another
  - [`externalCatalog`](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/internal/SharedState.scala#L149) (L149) — the Hive/in-memory metastore connection
  - [`globalTempDB`](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/internal/SharedState.scala#L180) (L180) — the database backing `createGlobalTempView`, and the reason global temp views outlive the session that made them
- [SessionState.scala:71](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/internal/SessionState.scala#L71) — **one per session**: SQL conf, temp views, UDF registry, analyzer, optimizer, planner
- [BaseSessionStateBuilder.scala:65](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/internal/BaseSessionStateBuilder.scala#L65) — assembles it; `catalog` (L147), `catalogManager` (L163), `analyzer` (L192), `build()` (L454). `SessionCatalog` ([SessionCatalog.scala:87](https://github.com/apache/spark/blob/v4.2.0/sql/catalyst/src/main/scala/org/apache/spark/sql/catalyst/catalog/SessionCatalog.scala#L87)) is where temp-view-vs-table resolution order is decided

### Extensions — the supported way to change the engine

- [SparkSessionExtensions.scala:109](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/SparkSessionExtensions.scala#L109) — injection points: `injectResolutionRule` (L223), `injectOptimizerRule` (L308), `injectPlannerStrategy` (L338)
- [classic/SparkSession.scala:1255](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/classic/SparkSession.scala#L1255) — `applyExtensions`, driven by `spark.sql.extensions` (`StaticSQLConf.SPARK_SESSION_EXTENSIONS`, read at L1258) and invoked during build at L1050. ### Termination

- [classic/SparkSession.scala:853](https://github.com/apache/spark/blob/v4.2.0/sql/core/src/main/scala/org/apache/spark/sql/classic/SparkSession.scala#L853) — `close()`: `stop()` is an alias. Stopping a session stops the underlying `SparkContext`, which is why one careless `spark.stop()` in a notebook invalidates every other session on the JVM — the `SharedState` goes with it

### The Connect session

- [SessionHolder.scala:56](https://github.com/apache/spark/blob/v4.2.0/sql/connect/server/src/main/scala/org/apache/spark/sql/connect/service/SessionHolder.scala#L56) — `SessionHolder(userId, sessionId, session)`: server-side, a Connect session is keyed by user *and* session id and holds a real `SparkSession`. The client object is a handle; the state described above lives on the server, which is what makes the classic-vs-Connect distinction concrete rather than cosmetic

- **`local[N,M]` syntax** — added to Exercise 3 table: N threads + M max task failures; the only way to test retry logic in local mode.
- **3-layer class split** — added to "Classic mode vs Spark Connect": `sql.SparkSession` (abstract), `sql.classic.SparkSession`, `sql.connect.SparkSession`; surfaces in stack traces.
- **REPL bootstrap** — added after "Classic mode vs Spark Connect": `shell.py` / `_create_shell_session()` binds `spark`, `sc`, `sql`, `sqlContext` globals; no builder call needed in the `pyspark` shell.

### Not in spark-book — needs addition ❌

The 2026-06-06 pass closed every gap against 4.1.2. Re-tracing against 4.2.0 opens one, and confirms Ch04 is otherwise clean:

- **Connect-mode session configs are new surface.** Spark 4.2.0 carries eleven `spark.connect.session.*` configs that did not exist when Ch04 was written — plan caching (`planCache.enabled`, `alwaysCacheDataSourceReadsEnabled`), plan compression (`planCompression.threshold`, `defaultAlgorithm`), result chunking (`resultChunking.maxChunkSize`), and the ML cache memory controls. Ch04 covers *which* session implementation you get; it says nothing about what the Connect server does with the plan once you have one. Worth a short subsection, since these are the knobs that matter when a Connect session behaves differently from a classic one.

The completeness pass adds four more, all things the earlier trace never looked at:

- **`SharedState` vs `SessionState` is the model behind `newSession()`.** Ch04 explains that `newSession()` gives isolated temp views over the same `SparkContext`, but not *why*: `SharedState` (one per context) owns the cache manager, external catalog and global temp database; `SessionState` (one per session) owns conf, temp views and UDFs. With that split stated, the behaviour of `newSession`, `cloneSession` and global temp views stops needing to be memorised.
- **`spark.cache()` crosses sessions.** The `cacheManager` lives on `SharedState`, so a DataFrame cached in one session is visible to another. Surprising, and absent from the chapter.
- **`spark.sql.extensions` is how the ecosystem attaches.** Iceberg, Delta and Sedona all install themselves through `SparkSessionExtensions` via a *static* config, which cannot be set after the session exists. This is a common first failure when adding a table format, and Ch04 is the natural place for it.
- **`stop()` stops the `SparkContext`.** Closing one session tears down `SharedState` for every session on the JVM. Worth one line in a chapter that teaches `newSession()`.

Ch04's builder, `getOrCreate` trap, static-vs-runtime config, `newSession`/`cloneSession`/`create`, `local[N,M]`, three-layer class split and REPL bootstrap material all re-verified against 4.2.0 and still hold.
