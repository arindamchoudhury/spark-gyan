## What it is

`SparkSession` is the single entry point to Spark's DataFrame and Dataset API. It wraps a `SparkContext` (which owns the cluster connection and scheduler) inside a richer SQL-aware layer that also holds a `SharedState` (warehouse, cache, external catalog — shared across sessions on the same JVM) and a `SessionState` (SQL config, temp views, UDFs, parser — isolated per session). The fluent `Builder` API collects configuration before constructing or reusing a session; two class-level slots — a thread-local active session and a global default session — govern reuse and isolation throughout the application lifetime.

## Relevant configs

| Config | Default | Effect |
|---|---|---|
| `spark.app.name` | random UUID | Application name in Spark UI and logs |
| `spark.master` | (required) | Cluster URL; `local`, `local[N]`, `local[*]`, `local[N,M]`, `spark://host:port`, etc. |
| `spark.log.level` | None (uses log4j2 config) | Overrides Log4j2 root logger at `SparkContext` startup; syncs to executors if `spark.executor.allowSyncLogLevel=true` |
| `spark.sql.catalogImplementation` | `in-memory` | `hive` activates `HiveSessionStateBuilder` and connects to HMS |
| `spark.sql.warehouse.dir` | `./spark-warehouse` | Default location for managed tables |
| `spark.sql.session.timeZone` | JVM default timezone | Session-level timezone for datetime operations |
| `spark.pyspark.python` | None (uses `python3` on PATH) | Python executable used on executors |
| `spark.pyspark.driver.python` | None (falls back to `spark.pyspark.python`) | Python executable on the driver |
| `spark.python.worker.reuse` | `true` | Keeps Python worker processes alive across tasks; required for `ModelCache`, reduces startup cost |
| `spark.submit.deployMode` | `client` | `client` = driver runs locally; `cluster` = driver on a cluster node (non-local masters only) |
| `spark.executor.isolatedSessionCache.size` | 100 | Sessions for which executor-side per-session state is cached (Connect server mode) |
| `spark.executor.pyspark.memory` | None (unlimited) | Off-heap memory limit for Python workers on executors |
| `spark.api.mode` | auto-detected | `classic` or `connect`; selects which session implementation `SparkSession.builder` constructs |

## Chapter notes

The Rioux book (Spark 3.2 era) shows the basic builder pattern correctly but misses several things the source reveals:

**Architecture split (new in Spark 4.x):** The session class is now three layers — abstract `sql.SparkSession` API, `sql.classic.SparkSession` implementation, and `sql.connect.SparkSession`. The book's code still works because PySpark routes to Classic unless `SPARK_REMOTE` or `spark.api.mode=connect` is set.

**`create()` vs `getOrCreate()`:** The book only shows `getOrCreate()`. `create()` (added in 3.5.0) always forces a new session even when an active one exists — useful in test harnesses that need session isolation.

**`newSession()` vs `cloneSession()`:** `newSession()` shares `SharedState` but starts a fresh `SessionState`. `cloneSession()` additionally copies the current `SessionState` (configs, UDFs) and `managedJobTags`, then forces eager initialization — the right tool when an isolated child must inherit the parent's current configuration snapshot.

**Static vs modifiable configs:** When `getOrCreate()` returns an existing session, it applies builder options via `applyModifiableSettings`, which silently skips static configs. A common confusion: setting `spark.sql.warehouse.dir` in a builder that finds an existing session has no effect.

**`spark.log.level` vs `setLogLevel()`:** Setting `spark.log.level` in `SparkConf` before session creation is preferable to calling `sc.setLogLevel()` post-hoc — it fires before any Spark logging, and also propagates to executors if `spark.executor.allowSyncLogLevel` is enabled.

**`local[*]` thread count:** Uses `Runtime.getRuntime.availableProcessors()` at scheduler-creation time (not JVM start). `local[N,M]` sets max task retries to M — useful for testing failure-recovery logic, not just parallelism.

**PySpark Py4J bridge:** Python `Builder.getOrCreate` → `SparkContext.getOrCreate` → `SparkSession(sc, options)` → JVM constructor `jvm.org.apache.spark.sql.classic.SparkSession(jsc.sc(), options)`. The options `HashMap` is passed directly so extensions and modifiable settings are applied atomically.
