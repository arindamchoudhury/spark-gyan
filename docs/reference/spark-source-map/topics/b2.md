## What it is

`SparkSession` is the single entry point to Spark's DataFrame and Dataset API. It wraps a `SparkContext` (which owns the cluster connection and scheduler) inside a richer SQL-aware layer that also holds a `SharedState` (warehouse, cache, external catalog — shared across sessions on the same JVM) and a `SessionState` (SQL config, temp views, UDFs, parser — isolated per session). The fluent `Builder` API collects configuration before constructing or reusing a session; two class-level slots — a thread-local active session and a global default session — govern reuse and isolation throughout the application lifetime.

## Relevant configs

| Config | Default | Effect |
|---|---|---|
| `spark.app.name` | random UUID | Application name in Spark UI and logs |
| `spark.master` | (required) | Cluster URL; `local`, `local[N]`, `local[*]`, `local[N,M]`, `spark://host:port`, etc. |
| `spark.log.level` | None (uses log4j2 config) | Overrides Log4j2 root logger at `SparkContext` startup; syncs to executors if `spark.executor.allowSyncLogLevel=true` |
| `spark.sql.catalogImplementation` | `in-memory` | `hive` activates `HiveSessionStateBuilder` and connects to HMS |
| `spark.sql.warehouse.dir` | `./spark-warehouse` | Default location for managed tables |
| `spark.sql.session.timeZone` | JVM default timezone | Session-level timezone for datetime operations |
| `spark.pyspark.python` | None (uses `python3` on PATH) | Python executable used on executors |
| `spark.pyspark.driver.python` | None (falls back to `spark.pyspark.python`) | Python executable on the driver |
| `spark.python.worker.reuse` | `true` | Keeps Python worker processes alive across tasks; required for `ModelCache`, reduces startup cost |
| `spark.submit.deployMode` | `client` | `client` = driver runs locally; `cluster` = driver on a cluster node (non-local masters only) |
| `spark.executor.isolatedSessionCache.size` | 100 | Sessions for which executor-side per-session state is cached (Connect server mode) |
| `spark.executor.pyspark.memory` | None (unlimited) | Off-heap memory limit for Python workers on executors |
| `spark.api.mode` | auto-detected | `classic` or `connect`; selects which session implementation `SparkSession.builder` constructs |

## Chapter notes

Gap analysis against **spark-book Ch 04** (`spark-book/ch04-sparksession.md`).

### Already in spark-book ✅

- Builder pattern, `getOrCreate()` trap, static vs runtime configs, `spark.conf.isModifiable()` — well covered with working examples.
- `newSession()` for isolated namespaces sharing one `SparkContext` — covered with a Mermaid diagram.
- `local[*]` using `availableProcessors()` — in Exercise 3.
- Classic vs Connect split — covered; `spark.api.mode`, `SPARK_REMOTE`, `.remote()` builder all mentioned.
- **`cloneSession()`** — added after `newSession()` section: copies parent's `SessionState` (configs, UDFs, job tags); contrasted with `newSession()` (fresh state) and `create()` (test isolation).
- **`create()` method** — added alongside `cloneSession()`: always forces a new session; prevents accidental reuse in test harnesses.
- **`spark.log.level` config** — added to "Settings worth knowing for local work": fires at startup before any logging, propagates to executors via `spark.executor.allowSyncLogLevel`; preferred over post-startup `setLogLevel()`.
- **`local[N,M]` syntax** — added to Exercise 3 table: N threads + M max task failures; the only way to test retry logic in local mode.
- **3-layer class split** — added to "Classic mode vs Spark Connect": `sql.SparkSession` (abstract), `sql.classic.SparkSession`, `sql.connect.SparkSession`; surfaces in stack traces.
- **REPL bootstrap** — added after "Classic mode vs Spark Connect": `shell.py` / `_create_shell_session()` binds `spark`, `sc`, `sql`, `sqlContext` globals; no builder call needed in the `pyspark` shell.

### Not in spark-book — needs addition ❌

The 2026-06-06 pass closed every gap against 4.1.2. Re-tracing against 4.2.0 opens one, and confirms Ch04 is otherwise clean:

- **Connect-mode session configs are new surface.** Spark 4.2.0 carries eleven `spark.connect.session.*` configs that did not exist when Ch04 was written — plan caching (`planCache.enabled`, `alwaysCacheDataSourceReadsEnabled`), plan compression (`planCompression.threshold`, `defaultAlgorithm`), result chunking (`resultChunking.maxChunkSize`), and the ML cache memory controls. Ch04 covers *which* session implementation you get; it says nothing about what the Connect server does with the plan once you have one. Worth a short subsection, since these are the knobs that matter when a Connect session behaves differently from a classic one.

Ch04's builder, `getOrCreate` trap, static-vs-runtime config, `newSession`/`cloneSession`/`create`, `local[N,M]`, three-layer class split and REPL bootstrap material all re-verified against 4.2.0 and still hold.
