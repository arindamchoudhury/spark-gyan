## What it is

An RDD (Resilient Distributed Dataset) is the foundational abstraction in Apache Spark: an immutable, partitioned, lazily-evaluated collection that records its lineage (how it was derived from parent RDDs) rather than its data. Every RDD subclass must implement five abstract hooks — `compute`, `getPartitions`, `getDependencies`, `getPreferredLocations`, and `partitioner` — and Spark's scheduler uses this metadata to plan stages, detect shuffle boundaries, and recover from failures by recomputing only the lost partitions. DataFrames and Datasets are built on top of RDDs and cover the vast majority of production workloads, but direct RDD use remains necessary for Python UDFs over arbitrary objects, custom partitioning strategies, interoperability with third-party Hadoop/Spark ecosystem libraries, and cases requiring fine-grained control over serialization or partition placement.

## Code path

### sc.parallelize()

`sc.parallelize(seq, numSlices = defaultParallelism)` — [SparkContext.scala:1016](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/SparkContext.scala#L1016)

`defaultParallelism` resolves via `taskScheduler.defaultParallelism()`. For `CoarseGrainedSchedulerBackend` the formula is `conf.getInt("spark.default.parallelism", max(totalCoreCount, 2))`. When unset, the number of available cores across all executors is used, falling back to 2 at minimum.

`parallelize` constructs a `ParallelCollectionRDD` — [ParallelCollectionRDD.scala:85](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/ParallelCollectionRDD.scala#L85). Its `getPartitions` calls the companion object's `slice()` helper (line 117) which encodes `Range` and `NumericRange` as sub-ranges rather than materializing the values — so `sc.parallelize(1 to 1_000_000_000, 4)` is memory-safe. For arbitrary sequences it slices by index: `start = (i * length) / numSlices`.

### Transformation dispatch

`rdd.map(f)` — [RDD.scala:424](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L424)

The closure `f` is first cleaned (`sc.clean(f)`) — this analysis strips unnecessary outer-scope references to reduce serialization bloat. The cleaned function is wrapped into a `MapPartitionsRDD` where each partition applies `iter.map(cleanF)`.

`flatMap` — [RDD.scala:436](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L436) — follows the same path using `iter.flatMap(cleanF)`.

`filter` — [RDD.scala:444](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L444) — also a `MapPartitionsRDD` but sets `preservesPartitioning = true`, keeping any existing partitioner downstream.

`mapPartitions` — [RDD.scala:863](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L863) — exposes the partition iterator directly to user code, amortizing per-row overhead (e.g., one database connection per partition rather than one per row).

### Action dispatch

`collect()` — [RDD.scala:1072](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1072) — calls `sc.runJob(this, (iter: Iterator[T]) => iter.toArray)` across all partitions and concatenates on the driver.

`reduce(f)` — [RDD.scala:1146](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1146) — two-level merge: each partition reduces locally (`iter.reduceLeft(cleanF)`, returning `Option[T]`); the driver merges partition results via the same function `f`. Because the driver-side merge also uses `f`, the function must be commutative and associative.

`take(n)` — [RDD.scala:1489](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1489) — adaptive multi-round scan: first tries `spark.rdd.limit.initialNumPartitions` (default 1); if still short, scales up: `partsScanned * scaleUpFactor` when the buffer is empty, or `ceil(1.5 * left * partsScanned / buf.size)` otherwise (cap: `scaleUpFactor` × previous count).

`foreachPartition(f)` — [RDD.scala:1061](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1061) — identical structure to `collect` but the per-partition closure returns `Unit`; no result pulled to driver.

### iterator() dispatch

`RDD.iterator(split, context)` — [RDD.scala:334](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L334) — the central per-partition dispatch on each executor:

- `storageLevel != NONE` → `getOrCompute`: tries `BlockManager` first; on miss, computes and stores.
- Otherwise → `computeOrReadCheckpoint` (line 369): if checkpointed and materialized, reads from the `CheckpointRDD` parent; else calls `compute(split, context)` directly.

### CoGroupedRDD: narrow vs wide detection

`CoGroupedRDD.getDependencies()` — [CoGroupedRDD.scala:98](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/CoGroupedRDD.scala#L98) — for each input RDD checks `rdd.partitioner == Some(part)`: match → `OneToOneDependency` (narrow, no shuffle); no match → `ShuffleDependency` (wide). This is the exact mechanism that makes pre-partitioned joins shuffle-free.

### Checkpoint mechanics

`rdd.checkpoint()` — [RDD.scala:1686](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1686) — creates a `ReliableRDDCheckpointData` attachment; nothing is written yet.

`doCheckpoint()` — [RDD.scala:1957](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1957) — called automatically after the first action; recursively checkpoints ancestors, then calls `ReliableRDDCheckpointData.doCheckpoint()` — [ReliableRDDCheckpointData.scala:60](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/ReliableRDDCheckpointData.scala#L60) — which writes to HDFS and optionally registers checkpoint files for GC cleanup.

`markCheckpointed()` — [RDD.scala:1981](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1981) — drops all parent RDD references and clears `partitions_`, replacing the full lineage with a single dependency on the new `CheckpointRDD`.

### PySpark Python-JVM bridge

`RDD.map(f)` in PySpark — [rdd.py:580](https://github.com/apache/spark/blob/v4.2.0/python/pyspark/core/rdd.py#L580) — wraps `f` inside `lambda _: map(f, iterator)` and delegates to `mapPartitionsWithIndex` (line 709), constructing a `PipelinedRDD`.

`PipelinedRDD` — [rdd.py:5252](https://github.com/apache/spark/blob/v4.2.0/python/pyspark/core/rdd.py#L5252) — chains consecutive Python transformations: when the parent is also a non-cached `PipelinedRDD`, it composes functions into a single `pipeline_func` (lines 5305–5308), so only one Python worker call is needed per partition for the entire chain. A `cache()` or `checkpoint()` breaks the pipeline.

`_prepare_for_python_RDD` — [rdd.py:5104](https://github.com/apache/spark/blob/v4.2.0/python/pyspark/core/rdd.py#L5104) — cloudpickles the `(func, profiler, deserializer, serializer)` tuple via `CloudPickleSerializer`; payloads exceeding 1 MB are automatically broadcast instead of embedded per-task.

`collect()` in PySpark — [rdd.py:1669](https://github.com/apache/spark/blob/v4.2.0/python/pyspark/core/rdd.py#L1669) — calls `PythonRDD.collectAndServe` over Py4J; results return via a local socket through `_load_from_socket`.

### TorrentBroadcast

Driver divides the serialized broadcast object into `spark.broadcast.blockSize` (4 MB) chunks — [TorrentBroadcast.scala:139](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/broadcast/TorrentBroadcast.scala#L139). Each executor fetches blocks in random shuffle order — [TorrentBroadcast.scala:189](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/broadcast/TorrentBroadcast.scala#L189) — from both the driver and peer executors that have already downloaded some blocks, preventing the driver from becoming a bottleneck.

## Relevant configs

| Config | Default | Effect |
|---|---|---|

- **`df.rdd` does not work under Spark Connect.** `pyspark.sql.connect.dataframe.DataFrame.rdd` raises `PySparkNotImplementedError`, and the Connect client has no `RDD` class at all. Since Connect is the default `pyspark` REPL mode in 4.x, **the entire contents of this chapter are classic-mode only** — which is a scoping statement the chapter needs at the top, not a footnote. Note the 4.2.0 release notes' "RDD API compatibility ([SPARK-55227])" heading is misleading here: the items under it (`DataFrame.zipWithIndex`, `Dataset.zipWithIndex`, `DataFrame.toJSON`) are DataFrame methods that *reduce the need* for RDDs under Connect, not RDD support.
- **Closure cleaning is what produces `Task not serializable`.** `SparkContext.clean` ([SparkContext.scala:2850](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/SparkContext.scala#L2850)) runs on every closure passed to a transformation, nulling out unreferenced outer-object fields before serialization. The chapter covers the closure-capture *bug* (the counter that never counts) but not the machinery, so the most common RDD error message has no explanation attached. See also the optional-depth topic I14.
- **RDD aggregations spill, with their own machinery.** `ExternalAppendOnlyMap` ([ExternalAppendOnlyMap.scala:56](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/util/collection/ExternalAppendOnlyMap.scala#L56)) and `ExternalSorter` ([ExternalSorter.scala:95](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/util/collection/ExternalSorter.scala#L95)) back `combineByKey`-family operations and shuffle writes. This is the RDD-level analogue of the aggregate spill in B6, and it is why `groupByKey` on skewed data degrades rather than failing outright.
- **`repartition` is `coalesce(n, shuffle = true)`.** [RDD.scala:488](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L488) delegates to [RDD.scala:514](https://github.com/apache/spark/blob/v4.2.0/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L514). One method, one boolean — which makes "coalesce avoids a shuffle, repartition forces one" a fact about an argument rather than two APIs to memorise. Relevant to I5.
- **`take()` can run several jobs.** The adaptive scan the chapter already documents means a single `take(n)` may submit multiple jobs, which is visible in the Spark UI and confuses job-count expectations.
