## What it is

An RDD (Resilient Distributed Dataset) is the foundational abstraction in Apache Spark: an immutable, partitioned, lazily-evaluated collection that records its lineage (how it was derived from parent RDDs) rather than its data. Every RDD subclass must implement five abstract hooks — `compute`, `getPartitions`, `getDependencies`, `getPreferredLocations`, and `partitioner` — and Spark's scheduler uses this metadata to plan stages, detect shuffle boundaries, and recover from failures by recomputing only the lost partitions. DataFrames and Datasets are built on top of RDDs and cover the vast majority of production workloads, but direct RDD use remains necessary for Python UDFs over arbitrary objects, custom partitioning strategies, interoperability with third-party Hadoop/Spark ecosystem libraries, and cases requiring fine-grained control over serialization or partition placement.

## Code path

### sc.parallelize()

`sc.parallelize(seq, numSlices = defaultParallelism)` — [SparkContext.scala:1016](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/SparkContext.scala#L1016)

`defaultParallelism` resolves via `taskScheduler.defaultParallelism()`. For `CoarseGrainedSchedulerBackend` the formula is `conf.getInt("spark.default.parallelism", max(totalCoreCount, 2))`. When unset, the number of available cores across all executors is used, falling back to 2 at minimum.

`parallelize` constructs a `ParallelCollectionRDD` — [ParallelCollectionRDD.scala:85](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/ParallelCollectionRDD.scala#L85). Its `getPartitions` calls the companion object's `slice()` helper (line 117) which encodes `Range` and `NumericRange` as sub-ranges rather than materializing the values — so `sc.parallelize(1 to 1_000_000_000, 4)` is memory-safe. For arbitrary sequences it slices by index: `start = (i * length) / numSlices`.

### Transformation dispatch

`rdd.map(f)` — [RDD.scala:424](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L424)

The closure `f` is first cleaned (`sc.clean(f)`) — this analysis strips unnecessary outer-scope references to reduce serialization bloat. The cleaned function is wrapped into a `MapPartitionsRDD` where each partition applies `iter.map(cleanF)`.

`flatMap` — [RDD.scala:433](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L433) — follows the same path using `iter.flatMap(cleanF)`.

`filter` — [RDD.scala:441](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L441) — also a `MapPartitionsRDD` but sets `preservesPartitioning = true`, keeping any existing partitioner downstream.

`mapPartitions` — [RDD.scala:860](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L860) — exposes the partition iterator directly to user code, amortizing per-row overhead (e.g., one database connection per partition rather than one per row).

### Action dispatch

`collect()` — [RDD.scala:1056](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1056) — calls `sc.runJob(this, (iter: Iterator[T]) => iter.toArray)` across all partitions and concatenates on the driver.

`reduce(f)` — [RDD.scala:1130](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1130) — two-level merge: each partition reduces locally (`iter.reduceLeft(cleanF)`, returning `Option[T]`); the driver merges partition results via the same function `f`. Because the driver-side merge also uses `f`, the function must be commutative and associative.

`take(n)` — [RDD.scala:1473](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1473) — adaptive multi-round scan: first tries `spark.rdd.limit.initialNumPartitions` (default 1); if still short, scales up: `partsScanned * scaleUpFactor` when the buffer is empty, or `ceil(1.5 * left * partsScanned / buf.size)` otherwise (cap: `scaleUpFactor` × previous count).

`foreachPartition(f)` — [RDD.scala:1045](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L1045) — identical structure to `collect` but the per-partition closure returns `Unit`; no result pulled to driver.

### iterator() dispatch

`RDD.iterator(split, context)` — [RDD.scala:334](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L334) — the central per-partition dispatch on each executor:

- `storageLevel != NONE` → `getOrCompute`: tries `BlockManager` first; on miss, computes and stores.
- Otherwise → `computeOrReadCheckpoint` (line 369): if checkpointed and materialized, reads from the `CheckpointRDD` parent; else calls `compute(split, context)` directly.

### CoGroupedRDD: narrow vs wide detection

`CoGroupedRDD.getDependencies()` — [CoGroupedRDD.scala:98](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/CoGroupedRDD.scala#L98) — for each input RDD checks `rdd.partitioner == Some(part)`: match → `OneToOneDependency` (narrow, no shuffle); no match → `ShuffleDependency` (wide). This is the exact mechanism that makes pre-partitioned joins shuffle-free.

### PySpark Python-JVM bridge

`RDD.map(f)` in PySpark — [rdd.py:582](https://github.com/apache/spark/blob/v4.1.2/python/pyspark/core/rdd.py#L582) — wraps `f` inside `lambda _: map(f, iterator)` and delegates to `mapPartitionsWithIndex` (line 709), constructing a `PipelinedRDD`.

`PipelinedRDD` — [rdd.py:5267](https://github.com/apache/spark/blob/v4.1.2/python/pyspark/core/rdd.py#L5267) — chains consecutive Python transformations: when the parent is also a non-cached `PipelinedRDD`, it composes functions into a single `pipeline_func` (lines 5305–5308), so only one Python worker call is needed per partition for the entire chain. A `cache()` or `checkpoint()` breaks the pipeline.

`_prepare_for_python_RDD` — [rdd.py:5118](https://github.com/apache/spark/blob/v4.1.2/python/pyspark/core/rdd.py#L5118) — cloudpickles the `(func, profiler, deserializer, serializer)` tuple via `CloudPickleSerializer`; payloads exceeding 1 MB are automatically broadcast instead of embedded per-task.

`collect()` in PySpark — [rdd.py:1670](https://github.com/apache/spark/blob/v4.1.2/python/pyspark/core/rdd.py#L1670) — calls `PythonRDD.collectAndServe` over Py4J; results return via a local socket through `_load_from_socket`.

### TorrentBroadcast

Driver divides the serialized broadcast object into `spark.broadcast.blockSize` (4 MB) chunks — [TorrentBroadcast.scala:139](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/broadcast/TorrentBroadcast.scala#L139). Each executor fetches blocks in random shuffle order — [TorrentBroadcast.scala:195](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/broadcast/TorrentBroadcast.scala#L195) — from both the driver and peer executors that have already downloaded some blocks, preventing the driver from becoming a bottleneck.

### Not in spark-book — needs addition ❌

- **`spark.default.parallelism` derivation formula** — when unset, `defaultParallelism` equals the total core count across all executors (minimum 2); `parallelize` and `range` default to this value, and `Partitioner.defaultPartitioner` also consults it when determining shuffle output partition count. Practitioners need to understand this to size shuffle partitions deliberately rather than accepting an accidental default.

- **`parallelize` Range-optimization** — `ParallelCollectionRDD.slice()` encodes `Range` and `NumericRange` collections as sub-ranges rather than copying element values; `sc.parallelize(1 to 1_000_000_000, 4)` never materializes a billion integers on the driver. This is the reason `sc.range()` is recommended over `sc.parallelize(range(...))`.

- **`rdd.toDebugString()`** — prints the full RDD lineage with partition counts, storage level annotations, and shuffle stage boundaries marked with `+-(N)`. The primary diagnostic tool for inspecting DAG structure before running a job.

- **`rdd.getNumPartitions()`** — `final def getNumPartitions: Int = partitions.length` (RDD.scala:317); needed for verifying partition count before and after `repartition`/`coalesce`.

- **`rdd.id` / `rdd.name` / `rdd.setName()`** — every RDD receives a monotonically increasing integer ID from `sc.newRddId()` at construction; the mutable `name` field and `setName()` propagate to the Spark UI job and stage names, making long-running pipelines easier to debug.

- **`glom()`** — [RDD.scala:735](https://github.com/apache/spark/blob/v4.1.2/core/src/main/scala/org/apache/spark/rdd/RDD.scala#L735) — collapses all elements of each partition into a single `Array[T]`, returning `RDD[Array[T]]`. The essential tool for inspecting per-partition contents and confirming partition skew without a shuffle.

- **`mapPartitions` as the low-overhead alternative to `map`** — ch05 lists `mapPartitions` in the transformations table but does not explain why it exists: it accepts an iterator-to-iterator function called once per partition, so per-partition initialization cost (database connection, compiled regex, loaded ML model) is paid once, not once per row.

- **`spark.serializer` and the Kryo switch** — the default `JavaSerializer` is safe but slow for numeric and case-class RDDs; replacing it with `KryoSerializer` and registering classes via `spark.kryo.classesToRegister` can reduce serialized size and CPU time significantly. This config is not mentioned in ch05.

- **`spark.rdd.compress` and `spark.io.compression.codec` interaction** — ch05 covers storage levels but not the separate `spark.rdd.compress` toggle that compresses serialized partition bytes in the BlockManager on top of the chosen storage level; applies the configured codec (default LZ4).

- **TorrentBroadcast peer-to-peer block distribution** — ch05 says broadcast sends one copy per executor; the actual mechanism is BitTorrent-style: the driver splits data into 4 MB blocks and each executor fetches blocks in shuffled order from both the driver and from peers that have already downloaded some blocks, preventing the driver from becoming a bottleneck on large broadcasts (>100 MB).

- **`spark.cleaner.referenceTracking.cleanCheckpoints`** — defaults to `false`; checkpoint files on HDFS accumulate indefinitely unless this flag is enabled. Practitioners running iterative algorithms who checkpoint every few iterations will fill their HDFS without knowing about this config.

- **`LongAccumulator.count` and `.avg`** — ch05 covers accumulators as write-only counters; `LongAccumulator` additionally tracks the number of `.add()` calls (`_count`) and exposes `.avg` — useful for computing per-element averages across a distributed computation without a separate `count()` action.

- **`take()` adaptive scanning algorithm** — ch05 lists `take` as an action but does not explain the multi-round logic: `take(1)` on a 10,000-partition RDD scans only 1 partition by default, not all 10,000. Understanding `spark.rdd.limit.initialNumPartitions` and `spark.rdd.limit.scaleUpFactor` is necessary to reason about `take` performance on skewed datasets.

- **`PipelinedRDD` function fusion in PySpark** — consecutive Python transformations on non-cached RDDs are fused into a single Python worker call per partition; inserting `cache()` or `checkpoint()` mid-chain breaks the pipeline and forces an extra round-trip. An unnecessary `.cache()` mid-chain can slow things down rather than speed them up.
