# Glossary

A running glossary of terms across all books. Each entry is attributed to its source.

## From Rioux (2022)

| Term | Meaning | Source |
| --- | --- | --- |
| **Action** | An operation that triggers actual data computation — e.g., `show()`, `write()`, `count()` on a data frame. Contrast with *transformation*. | Rioux Ch 1 |
| **Cluster manager** | The component that allocates computing resources (machines and executors) before a Spark job runs. Can be Spark Standalone, YARN, Mesos, or Kubernetes. | Rioux Ch 1 |
| **Driver program** | The process that hosts the user's code, translates it into Spark instructions, and coordinates executors. Sometimes called the master in older docs. | Rioux Ch 1 |
| **Eager evaluation** | Execution model where each instruction is performed immediately as it is received. Default in plain Python, pandas, R. Contrast with *lazy evaluation*. | Rioux Ch 1 |
| **Executor** | A JVM process that performs the actual data work on a worker node. Multiple executors can run on a single worker node. | Rioux Ch 1 |
| **Lazy evaluation** | Spark's execution model: transformations are recorded but not computed until an action is reached. Enables query optimization, memory efficiency, and fault recovery. | Rioux Ch 1 |
| **Master** | Legacy term for the entity that allocates cluster resources; being phased out in Spark docs. See *driver program* and *cluster manager*. | Rioux Ch 1 |
| **PySpark** | The Python API for Apache Spark. Exposes Spark's data processing capabilities through Python idioms. | Rioux Ch 1 |
| **pyspark.pandas** | A pandas-compatible API layered on top of PySpark (formerly the Koalas project; integrated into Spark as of 3.2.0). Allows pandas-style code to run at Spark scale. | Rioux Ch 1 |
| **RDD** | Resilient Distributed Dataset — Spark's low-level data structure. Predates the DataFrame API; still available but rarely the best choice for new code. | Rioux Ch 1 |
| **Scale out** | Adding more machines to a cluster rather than upgrading a single machine. Spark's primary scaling strategy. | Rioux Ch 1 |
| **Scale up** | Adding more CPU/RAM/disk to a single machine. Less cost-effective than scale-out past a certain threshold. | Rioux Ch 1 |
| **SparkContext** | The object encoding connection details and capacity configuration for a Spark cluster. | Rioux Ch 1 |
| **SparkSession** | The unified entry point to PySpark (introduced in Spark 2.0). Subsumes `SparkContext`, `SQLContext`, and `HiveContext`. | Rioux Ch 1 |
| **Transformation** | Any Spark operation that produces a new data frame without triggering computation — e.g., `select()`, `filter()`, `groupBy()`, `withColumn()`. Evaluated lazily. | Rioux Ch 1 |
| **Worker node** | A physical or virtual machine in the Spark cluster where executors run. | Rioux Ch 1 |
| **alias()** | Column method that renames the result of a column expression inside a `select()` call. Contrast with `withColumnRenamed()`. | Rioux Ch 2 |
| **DataFrameReader** | Object accessed via `spark.read`; provides format-specific methods (`text()`, `csv()`, `json()`, `parquet()`, `orc()`) to ingest data into a DataFrame. | Rioux Ch 2 |
| **ETL** | Extract, Transform, Load — the three-step pattern underpinning most data pipelines. PySpark maps naturally to this: read → transform → write. | Rioux Ch 2 |
| **explode()** | `pyspark.sql.functions` function that unpacks a column of arrays (or maps) into one row per element. Converts a `array<string>` column into a `string` column with more rows. | Rioux Ch 2 |
| **filter() / where()** | Identical DataFrame methods that keep only rows satisfying a Boolean column expression. `filter()` is the primary name; `where()` is an alias. | Rioux Ch 2 |
| **lower()** | `pyspark.sql.functions` function that lowercases all characters in a string column. | Rioux Ch 2 |
| **printSchema()** | DataFrame method that prints the column tree (names, types, nullability) to the console. One of the two primary exploration tools alongside `show()`. | Rioux Ch 2 |
| **regexp_extract()** | `pyspark.sql.functions` function that extracts a regex match group from a string column. Uses Java regex syntax. | Rioux Ch 2 |
| **REPL** | Read, Evaluate, Print, Loop — an interactive programming shell. The `pyspark` command launches a Python REPL pre-configured with `spark` and `sc`. | Rioux Ch 2 |
| **schema** | The description of a DataFrame's column names and their data types. Accessed via `printSchema()` (tree view), `.dtypes` (list of tuples), or `.schema` (programmatic `StructType` object). | Rioux Ch 2 |
| **select()** | The primary DataFrame transformation for choosing or computing columns. Equivalent to SQL `SELECT`. Accepts column objects, `col()` references, string names, or column expressions. | Rioux Ch 2 |
| **show()** | DataFrame **action** that triggers computation and prints up to N rows as an ASCII table. Parameters: `n`, `truncate`, `vertical`. | Rioux Ch 2 |
| **split()** | `pyspark.sql.functions` function that splits a string column by a Java regex delimiter, producing an `array<string>` column. | Rioux Ch 2 |
| **withColumnRenamed()** | DataFrame method that renames an existing column without otherwise changing the DataFrame. No-op if the named column doesn't exist. | Rioux Ch 2 |
| **coalesce(n)** | Transformation that reduces the number of partitions to `n` without a full shuffle. Use before writing to produce fewer output files. Contrast with `repartition(n)`. | Rioux Ch 3 |
| **DataFrameWriter** | Object accessed via `df.write`; mirrors DataFrameReader. Provides format-specific write methods (`csv()`, `parquet()`, `json()`) and a `mode()` setter (`overwrite`, `append`, `ignore`, `error`). | Rioux Ch 3 |
| **glob pattern** | A wildcard path like `*.txt` or a directory path that `spark.read` expands to match multiple files, loading them into a single unified DataFrame. | Rioux Ch 3 |
| **GroupedData** | Intermediate object returned by `groupBy()`. Holds grouped records and awaits an aggregation method (`count()`, `sum()`, `agg()`, …) to produce a new DataFrame. | Rioux Ch 3 |
| **groupBy()** | DataFrame transformation that groups rows by the values of one or more columns, returning a `GroupedData` object. Lowercase alias `groupby()` also accepted. | Rioux Ch 3 |
| **method chaining** | Calling the next transformation directly on the return value of the previous one, eliminating intermediate variables. Enabled by each transformation returning a new DataFrame. | Rioux Ch 3 |
| **orderBy()** | DataFrame transformation that sorts rows by one or more columns. Use `.desc()` on a `col()` or `ascending=False` for descending order. Alias: `sort()`. | Rioux Ch 3 |
| **partition** | A logical chunk of a distributed DataFrame, stored and processed by a single executor. PySpark writes one output file per partition by default. | Rioux Ch 3 |
| **repartition(n)** | Transformation that reshuffles data into exactly `n` partitions via a full shuffle. Use to increase partition count or rebalance skewed data. Contrast with `coalesce(n)`. | Rioux Ch 3 |
| **spark-submit** | CLI tool (`spark-submit script.py`) for submitting PySpark (and Scala/Java) programs to a Spark cluster in batch mode. The script must create its own `SparkSession`. | Rioux Ch 3 |
| **stop words** | Common words (the, a, of, to, …) that carry little semantic meaning and are typically removed before NLP analysis. | Rioux Ch 3 |
| **cast()** | Column method that converts a column to a specified type (e.g., `"int"`, `"double"`, `"timestamp"`). In Spark 4.x (ANSI mode on), invalid casts raise an error; use `try_cast()` for nullable semantics. | Rioux Ch 4 |
| **createDataFrame()** | `SparkSession` method that creates a DataFrame from a list-of-lists, a pandas DataFrame, or an RDD. Accepts a schema as a list of column names or a `StructType`. | Rioux Ch 4 |
| **denormalisation** | Merging multiple normalised tables into one wide ("fat") table to avoid join overhead. Preferred for analytical workloads in Spark. | Rioux Ch 4 |
| **describe()** | DataFrame method returning count, mean, stddev, min, max for numeric/string columns. For exploration only — output format not guaranteed stable across Spark versions. | Rioux Ch 4 |
| **distinct()** | DataFrame transformation that removes duplicate rows. Returns a new DataFrame with one copy of each unique row. | Rioux Ch 4 |
| **drop()** | DataFrame method that removes one or more named columns. Opposite of `select()`; dropping a non-existent column is a no-op. | Rioux Ch 4 |
| **EDA** | Exploratory Data Analysis — initial investigation of a new dataset to understand its structure, types, distributions, and quality before modelling. | Rioux Ch 4 |
| **inferSchema** | `spark.read.csv()` option (`True`/`False`) that auto-detects column types by pre-scanning the data. Convenient but expensive (reads data twice). | Rioux Ch 4 |
| **normalisation** | Data-modelling technique that eliminates redundancy by splitting data into multiple related tables linked by keys. Common in relational/SQL databases. | Rioux Ch 4 |
| **star schema** | Database schema with a central fact table (holding IDs and metrics) surrounded by dimension/link tables (holding the meaning of each ID). Common in data warehouses. | Rioux Ch 4 |
| **substr()** | Column method that extracts a substring: `col.substr(start, length)`. Position is **1-indexed** (not 0-indexed like Python strings). | Rioux Ch 4 |
| **summary()** | DataFrame method like `describe()` but with customisable statistics (e.g., `summary("min", "10%", "90%", "max")`). Counts only non-null values. | Rioux Ch 4 |
| **toDF()** | DataFrame method that renames **all** columns at once by accepting a new list of names (`df.toDF(*new_names)`). | Rioux Ch 4 |
| **toPandas()** | DataFrame action that collects the entire distributed DataFrame onto the driver as a pandas DataFrame. Only safe after aggregating to a small result. | Rioux Ch 4 |
| **try_cast()** | `pyspark.sql.functions` function (Spark 4.x) that attempts a type conversion and returns `null` on failure instead of raising an error. Replaces the Spark 3.x silent-null behaviour of `cast()` under ANSI mode. | Rioux Ch 4 |
| **withColumn()** | DataFrame method that adds a new column (or overwrites an existing one) while keeping all other columns intact. Signature: `withColumn(name, col_expr)`. | Rioux Ch 4 |
| **agg()** | `GroupedData` method that applies one or more aggregate functions (e.g., `F.sum()`, `F.avg()`) to each group and returns a new DataFrame. Preferred over calling aggregation methods directly on `GroupedData` because it accepts multiple functions and allows column aliasing. | Rioux Ch 5 |
| **crossJoin()** | DataFrame method (and `how="cross"` in `join()`) that returns every possible combination of left × right rows regardless of any predicate. Produces m × n output rows. | Rioux Ch 5 |
| **dropna()** | DataFrame method that removes rows containing null values. Parameters: `how` (`"any"` or `"all"`), `thresh` (min non-null count), `subset` (columns to inspect). Alias: `df.na.drop()`. | Rioux Ch 5 |
| **equi-join** | A join whose predicate tests equality between identically named columns. PySpark shorthand: pass the column name as a string to `on=`. Automatically deduplicates the join-key column in the result. | Rioux Ch 5 |
| **F.trim()** | `pyspark.sql.functions` function that removes leading and trailing whitespace characters from a string column. | Rioux Ch 5 |
| **F.when()** | `pyspark.sql.functions` function that creates a conditional column expression: `F.when(condition, value).when(...).otherwise(default)`. Omitting `.otherwise()` returns `null` for unmatched rows. Can be nested inside aggregate functions. | Rioux Ch 5 |
| **fillna()** | DataFrame method that replaces null values with a specified scalar value or a column-to-value dict. The fill value must be type-compatible with the column. Alias: `df.na.fill()`. | Rioux Ch 5 |
| **full outer join** | Join method (`how="outer"`, `"full"`, or `"full_outer"`) that returns all rows from both tables, padding unmatched sides with `null`. | Rioux Ch 5 |
| **GroupedData** | Transitional object returned by `groupby()`. Holds grouped records awaiting an aggregation method (`agg()`, `count()`, `sum()`, etc.) before becoming a DataFrame again. Has no `.show()` or `.select()`. | Rioux Ch 5 |
| **inner join** | Default join method (`how="inner"`). Returns only rows where the predicate is `True`. Duplicates a left row if it matches multiple right rows. | Rioux Ch 5 |
| **isin()** | Column method that returns `True` if the column value is a member of the supplied list. Used as `F.col("x").isin(["a", "b", "c"])`. | Rioux Ch 5 |
| **join()** | DataFrame method for combining two DataFrames. Three parameters: `on` (predicate or column name(s)), `how` (join method). Blueprint: `left.join(right, on=..., how=...)`. | Rioux Ch 5 |
| **left anti-join** | Join method (`how="left_anti"`) that returns only rows from the left table that have **no** matching row in the right table. The inverse of an inner join. | Rioux Ch 5 |
| **left join** | Join method (`how="left"` or `"left_outer"`) that returns all left rows; unmatched rows are padded with `null` for right-table columns. | Rioux Ch 5 |
| **left semi-join** | Join method (`how="left_semi"`) that returns left rows that match at least one right row. Only left-table columns are returned and matched left rows are not duplicated. | Rioux Ch 5 |
| **predicate** | In the context of a join, a Boolean column expression that determines whether a pair of left and right rows is considered a match. | Rioux Ch 5 |
| **right join** | Join method (`how="right"` or `"right_outer"`) that returns all right rows; unmatched rows are padded with `null` for left-table columns. | Rioux Ch 5 |
| **ArrayType** | PySpark complex column type holding an ordered list of values of the same type. Notation: `ArrayType(elementType)`. All elements must share one declared type; mixed-type arrays silently infer the lowest common denominator. | Rioux Ch 6 |
| **collect_list()** | `pyspark.sql.functions` aggregate that collapses rows into an array column. Preserves duplicates. Row order in the result array is **not** guaranteed. Inverse of `explode()`. | Rioux Ch 6 |
| **collect_set()** | `pyspark.sql.functions` aggregate like `collect_list()` but returns only distinct values. Order is not guaranteed. | Rioux Ch 6 |
| **complex type** | PySpark term for a column type that contains other types (also called *container* or *compound* type). The three complex types are `ArrayType`, `MapType`, and `StructType`. | Rioux Ch 6 |
| **explode()** | `pyspark.sql.functions` function that expands an array or map column into one row per element. Rows whose array/map column is **null are silently dropped** — use `explode_outer()` to retain them. | Rioux Ch 6 |
| **explode_outer()** | Like `explode()` but retains rows whose array/map is null, producing a null value for the exploded column instead of dropping the row. | Rioux Ch 6 |
| **FAILFAST** | `spark.read.json(mode="FAILFAST")` — reader mode that raises an error on any malformed record instead of setting it to null (the default `PERMISSIVE` behaviour). Surfaces schema mismatches at ingestion time. | Rioux Ch 6 |
| **JSON Lines** | File format where each line is a self-contained, newline-free JSON document. PySpark's default JSON reader expects this format: one line = one record. | Rioux Ch 6 |
| **MapType** | PySpark complex column type holding typed key-value pairs. Keys and values each have a declared type; keys cannot be null. Analogous to a Python dict but with type enforcement. Not produced by JSON ingestion — JSON objects become structs. | Rioux Ch 6 |
| **multiLine** | `spark.read.json(multiLine=True)` parameter that switches the read rule from "one line = one record" to "one file = one record", allowing JSON documents that span multiple lines. Note: camelCase with capital L. | Rioux Ch 6 |
| **partial schema** | Passing a `StructType` that covers only a subset of a JSON document's fields. PySpark reads only the declared fields, skipping the rest — useful for avoiding a full pre-scan of a very wide document. | Rioux Ch 6 |
| **posexplode()** | Like `explode()` but prepends a 0-based **position** column to the result. Returns two columns simultaneously, so it requires `.select("*", F.posexplode(...).alias("pos", "val"))` — `.withColumn()` cannot wrap it. | Rioux Ch 6 |
| **StructField** | A single named field in a `StructType`: `T.StructField(name, dataType, nullable=True)`. The building block of programmatic schema definition. | Rioux Ch 6 |
| **StructType** | PySpark type for a schema or a struct column: a collection of named `StructField` objects each with their own type. Represents both a full DataFrame schema (the root) and any nested struct column. | Rioux Ch 6 |
| **VARIANT** | Semi-structured column type introduced in Spark 4.0 (GA in 4.1) for JSON-like data that doesn't require a fixed schema at read time. Accessed with colon-sign operator syntax (`variant_col:field_name`). Produced by `parse_json()`. | Rioux Ch 6 (Spark 4.1 addition) |
| **catalog** | The `spark.catalog` property of `SparkSession`. Manages the metadata of all Spark SQL views and tables: `listTables()`, `dropTempView()`, and caching controls. | Rioux Ch 7 |
| **CTE (common table expression)** | SQL `WITH name AS (subquery)` syntax that names a sub-query at the top of a statement. Equivalent in PySpark is a Python function: intermediate DataFrames are scoped to the function body and cleaned up on return. | Rioux Ch 7 |
| **createOrReplaceTempView()** | DataFrame method that registers a DataFrame as a named Spark SQL view, making it queryable via `spark.sql()`. The `OrReplace` variant silently overwrites an existing view with the same name; the plain `createTempView()` raises an error if the name is already in use. | Rioux Ch 7 |
| **F.expr()** | `pyspark.sql.functions` function that wraps a SQL expression string into a Column object. Can be used inside `agg()`, `select()`, or `withColumn()`. | Rioux Ch 7 |
| **HAVING** | SQL clause that filters on aggregated columns after a `GROUP BY`. PySpark has no `having()` method; use `.where()` chained after `.agg()` instead. | Rioux Ch 7 |
| **selectExpr()** | DataFrame method that behaves like `select()` but accepts SQL expression strings (arithmetic, aliases, function calls). Convenient shorthand; prefer explicit `.alias()` for clarity. | Rioux Ch 7 |
| **spark.sql()** | `SparkSession` method that executes a SQL string against registered views and tables. Returns a DataFrame. | Rioux Ch 7 |
| **UNION ALL vs UNION** | SQL `UNION ALL` stacks rows from two queries and keeps duplicates. `UNION` deduplicates (more expensive). PySpark's `union()` is equivalent to `UNION ALL` — use `.distinct()` after if deduplication is needed. | Rioux Ch 7 |
| **higher-order function** | A function that takes another function as a parameter. `map()`, `filter()`, and `reduce()` on the RDD are all higher-order functions — they accept a Python function and apply it element-wise across the collection. | Rioux Ch 8 |
| **map() (RDD)** | RDD method that applies a function to every element and returns a new RDD with the results. The RDD equivalent of `withColumn()` / `select()` on a DataFrame. | Rioux Ch 8 |
| **filter() (RDD)** | RDD method that keeps only elements for which a predicate function returns a truthy value. Follows Python truthy/falsy rules (not strict `bool`), unlike the DataFrame's `where()`. | Rioux Ch 8 |
| **reduce() (RDD)** | RDD method that folds the collection to a single value by applying a two-argument function pair-wise. The function must be **commutative and associative** because Spark reduces partitions in parallel before merging. | Rioux Ch 8 |
| **RDD (resilient distributed dataset)** | The low-level distributed data container in Spark. Holds arbitrary Python objects (no schema, no column structure). Manipulated via higher-order functions (`map`, `filter`, `reduce`). Prefer DataFrames for structured data; use the RDD when the DataFrame's schema is genuinely a constraint. | Rioux Ch 8 |
| **SparkContext** | The entry point to the RDD API. Accessible as `spark.sparkContext` on a `SparkSession`. Provides `parallelize()` to convert a Python list to an RDD, and hosts all RDD creation methods. | Rioux Ch 8 |
| **UDF (user-defined function)** | A Python function promoted to operate on PySpark columns via `F.udf(fn, return_type)` or the `@F.udf(return_type)` decorator. Applies the function row-by-row (scalar). Slower than built-in functions due to Python–JVM serialisation overhead; use built-ins or pandas UDFs (Ch 9) when performance matters. | Rioux Ch 8 |
| **applyInPandas()** | `GroupedData` method that implements the group map UDF pattern: each group is passed as a `pd.DataFrame` to a plain Python function, and the returned `pd.DataFrame` is reassembled into a Spark DataFrame. Schema must be declared explicitly. | Rioux Ch 9 |
| **cold start** | An expensive initialisation operation (e.g., deserialising an ML model) that a UDF must perform before processing data. Iterator of Series UDFs amortise this cost by running it once per executor task rather than once per batch. | Rioux Ch 9 |
| **group aggregate UDF** | A pandas UDF (Series → scalar) used inside `.agg()` on a `GroupedData` object. Each group is collapsed to a single value. Also called Series to Scalar UDF. | Rioux Ch 9 |
| **group map UDF** | A pandas UDF (DataFrame → DataFrame) used with `applyInPandas()`. Each group arrives as a `pd.DataFrame`; the function returns a `pd.DataFrame`. Row count may change. | Rioux Ch 9 |
| **mapInPandas()** | `DataFrame` method that applies an iterator-based function across the full DataFrame (no group key). Receives and returns an iterator of `pd.DataFrame` objects. Useful for distributed inference of local ML models. | Rioux Ch 9 |
| **pandas UDF** | A PySpark UDF that operates on batches of rows serialised as pandas Series or DataFrames via PyArrow, rather than row-by-row. Decorated with `@F.pandas_udf(return_type)`. Significantly faster than Python UDFs for vectorisable operations. | Rioux Ch 9 |
| **PyArrow** | A Python library implementing the Apache Arrow columnar memory format. Used by PySpark to serialise data between the JVM and pandas UDFs. Zero-copy and cache-friendly; eliminates the per-row pickle overhead of Python UDFs. | Rioux Ch 9 |
| **Series to Series UDF** | The simplest pandas UDF type: takes one or more `pd.Series` as input, returns one `pd.Series`. Used like any column function in `withColumn()` or `select()`. Batch composition is not controlled by the user. | Rioux Ch 9 |
| **split-apply-combine** | A three-step data analysis pattern: (1) split the dataset into logical batches via `groupby()`, (2) apply a function to each batch independently, (3) combine results into a unified dataset. Implemented in PySpark via group aggregate and group map UDFs. | Rioux Ch 9 |
| **cume_dist()** | Analytical window function returning the fraction of records in the window whose ordered value is ≤ the current record's value. Range 0.0–1.0. Contrast with `percent_rank()`: cume_dist starts above 0 and counts the current row. | Rioux Ch 10 |
| **dense_rank()** | Ranking window function that assigns consecutive ranks with shared ranks for tied values and **no gaps** between ranks. Example: 1, 1, 2 (two ties, then next rank is 2). Contrast with `rank()` which leaves gaps. | Rioux Ch 10 |
| **feature leakage** | Using information about the future when building a predictive model. Window frame boundaries help prevent leakage — e.g., a `rangeBetween(unboundedPreceding, currentRow)` window only looks at past data. | Rioux Ch 10 |
| **lag(col, n, default)** | Analytical window function returning the value of `col` from the record `n` rows *before* the current row within the window. Returns `default` (null by default) when the offset exceeds the window boundary. Requires an ordered window. | Rioux Ch 10 |
| **lead(col, n, default)** | Analytical window function returning the value of `col` from the record `n` rows *after* the current row. Mirror of `lag()`. | Rioux Ch 10 |
| **ntile(n)** | Ranking window function that divides each window partition into `n` approximately equal buckets and assigns a bucket number (1 to n) to each record. Equivalent to quartiles (n=4), deciles (n=10), percentiles (n=100). | Rioux Ch 10 |
| **percent_rank()** | Ranking window function returning `(rank − 1) / (N − 1)` — a float in [0.0, 1.0] representing relative standing. The lowest value receives 0.0; the highest receives 1.0. | Rioux Ch 10 |
| **rank()** | Ranking window function that assigns nonconsecutive (olympic) ranks based on the ordered column value. Tied records share a rank; the next rank skips ahead by the number of ties. Example: 1, 1, 3. | Rioux Ch 10 |
| **rangeBetween(start, end)** | `WindowSpec` method that defines a frame whose boundaries are computed relative to the *value* of the current row's ordered column. Use for time/date windows of fixed duration. The ordered column must be numeric. | Rioux Ch 10 |
| **row_number()** | Ranking window function that assigns strictly increasing integers (1, 2, 3 …) to every record in the window regardless of ties. For tied values, the ordering among ties is nondeterministic unless all `orderBy()` columns uniquely identify each record. | Rioux Ch 10 |
| **rowsBetween(start, end)** | `WindowSpec` method that defines a frame whose boundaries are counted by row *position* relative to the current row. `Window.unboundedPreceding`, `Window.currentRow`, `Window.unboundedFollowing` are the named boundary constants. | Rioux Ch 10 |
| **window frame** | The subset of records within a window partition that is included in the computation for a given record. Defined by `rowsBetween()` or `rangeBetween()`. Default frame: unbounded for unordered windows; growing (up to currentRow) for ordered windows. | Rioux Ch 10 |
| **window function** | A function applied over a *window frame* that produces a new column for each record without reducing the data frame's row count. Three families: aggregate (`F.avg`, `F.sum`, …), ranking (`rank`, `row_number`, …), analytic (`lag`, `lead`, `cume_dist`). Applied via `.over(window_spec)`. | Rioux Ch 10 |
| **window partition** | The logical group of rows produced by `Window.partitionBy()`. Distinct from Spark's *physical* partitions (the executor-level data chunks). Spark processes each window partition independently when applying the window function. | Rioux Ch 10 |
| **WindowSpec** | Blueprint object produced by `Window.partitionBy()`, `.orderBy()`, `rowsBetween()`, or `rangeBetween()`. Encodes how the data frame should be split, ordered, and framed. Passed to `.over(window_spec)` on a Column expression. | Rioux Ch 10 |

## From the Spark source map

Terms that come from reading the Spark source rather than from any book — most of them name a rule or a mechanism you will meet in an `EXPLAIN` plan long before you meet it in print. Attribution is to the [source-map](spark-source-map/index.md) page that traced it.

| Term | Meaning | Source |
| --- | --- | --- |
| **Batch (Catalyst)** | A named group of optimizer or analyzer rules run under a strategy — `FixedPoint(n)` (re-run until the plan stops changing, capped at `n`) or `Once` (a single pass, checked for idempotence). The optimizer's ~28 batches, in order, are the map of the whole phase. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **CBO (cost-based optimizer)** | The part of Catalyst that chooses between plans using estimated row counts and sizes rather than fixed rules. Off by default (`spark.sql.cbo.enabled`), and inert without column statistics from `ANALYZE TABLE`. Its only real consumer is `CostBasedJoinReorder`. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Column statistics** | Per-column distinct count, min, max, null count, average/max length, and optionally a histogram, collected by `ANALYZE TABLE … COMPUTE STATISTICS FOR COLUMNS` and stored in the catalog. Distinct from table-level `sizeInBytes`, which Spark can estimate without them. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Constraint propagation** | Catalyst deriving facts that hold on every output row of a plan node (`a = b`, `IsNotNull(c)`) and propagating them upward, so `InferFiltersFromConstraints` can materialise them as real `Filter` nodes. It is why `isnotnull(joinKey)` appears in plans you never wrote. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **COUNT bug** | The wrong answer a correlated `COUNT` subquery gives after being rewritten to a left outer join: a non-matching outer row yields `NULL` where SQL requires `0`. Spark detects the vulnerable shape and compensates; three `legacy…IncorrectCountHandling` configs restore the old wrong result. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Decorrelation** | Rewriting a correlated subquery into a join, because Spark has no physical operator for one. Equality correlation becomes a group-by key; non-equality correlation needs a `DomainJoin`. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **DomainJoin** | A placeholder node introduced during decorrelation for non-equality correlation (`WHERE outer.c > inner.a`): the distinct set of outer values, joined into the subquery so the predicate can be evaluated locally. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **DPP (dynamic partition pruning)** | An optimizer rule that plants a `DynamicPruningSubquery` on a partitioned scan's partition column, so the large side lists only the partitions the small side actually produces. Requires a partitioned table; silently does nothing otherwise. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Excludable rule** | An optimizer rule that can be turned off by fully-qualified name via `spark.sql.optimizer.excludedRules`. About 25 rules are *non*-excludable because they are correctness rewrites (set operations, subqueries, float normalization) rather than optimizations. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Logical vs physical plan** | The optimizer works only on the *logical* plan — a tree of relational operators with no notion of partitions, shuffles or executors. Strategy selection, `Exchange` insertion and codegen all happen later, in the planner. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Predicate pushdown** | Moving a `Filter` below other operators so fewer rows flow upward — and, at the scan, into the data source itself. Blocked by non-determinism: a Python UDF or `rand()` in the predicate keeps it where it is, with no warning. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Runtime filter** | A filter on the large side of a join whose *values* are computed at run time from the small side. Two forms: DPP for partitioned scans, and an injected bloom filter (`BloomFilterMightContain`) for everything else. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **RuntimeReplaceable** | An expression that exists only for parsing and analysis and is expanded into its real implementation by `ReplaceExpressions` in the optimizer's first batch. It is why `EXPLAIN` on `nvl(a, b)` shows `coalesce`. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Schema pruning** | Narrowing the *read* schema so a columnar source reads only the fields used — including individual fields of a nested struct (`NestedColumnAliasing` rewrites the plan; `SchemaPruning` narrows the scan). | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
| **Star-schema detection** | A heuristic that identifies a fact table and its dimension tables by cardinality and referential-integrity ratios, used to constrain the join-reorder search space. | [sql/catalyst — optimizer](spark-source-map/sweeps/sql-catalyst-optimizer.md) |
